# 山西焦煤（000983）每日行情追踪与手机推送

每个交易日按你设定的时间自动抓取行情，生成一条适合手机屏幕阅读的短摘要，推送到你的手机。

---

超大单 +1993万 ｜ 大单 -645万

上例是程序实际输出的格式（`--dry-run` 实测结果，数值已与数据源逐项核对）。
开盘与上午十点两个时段的文案会自动切换为"现价 / 盘中快照"口径。

> "近 5 日主力合计"是由程序**用本地存档逐日累积**出来的：东财日线资金流接口是间歇可用的，

> 连续跑满 5 个交易日后即为完整的近 5 日合计，且从此不再依赖该接口。

## 三、快速开始（3 步）

```bash
cd jiaomei_tracker

# 1) 建虚拟环境并装依赖
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2) 先干跑一次，看看文案（不发送任何消息）
.venv\Scripts\python.exe run.py --all --dry-run

# 3) 配好推送通道后再注册计划任务
powershell -ExecutionPolicy Bypass -File scripts\install_task.ps1
```

> `scripts\install_task.ps1` 会自动在项目里找到 `.venv\Scripts\python.exe`，
> 读 `config.yaml` 里的时段，为每个时段注册一个"周一至周五"的计划任务。

## 四、配置：改成你要的时间

编辑 `config.yaml`：

```yaml
schedule:
  slots:
    - id: market_open
      name: "开盘"
      time: "09:35"      # ← 改这里
      intraday: true
    - id: morning_ten
      name: "上午十点"
      time: "10:00"
      intraday: true
    - id: market_close
      name: "下午三点"
      time: "15:02"      # ← 改这里
      intraday: false
```

- **增删时段**：加/删一条 `slots` 项即可。改完重跑一次 `install_task.ps1`（它会覆盖注册旧任务）。
- `intraday: true` 表示盘中快照，文案用"现价"；`false` 表示当日定稿，文案用"收盘"。
- **关于默认时间的说明**：
  - 开盘默认 `09:35` 而不是 `09:30`：09:30:00 整点的行情快照经常还没刷出当日开盘价，取 09:35 能确保拿到真实开盘价。要严格 09:30，改成 `"09:30"` 即可。
  - 收盘默认 `15:02` 而不是 `15:00`：A 股 14:57–15:00 是收盘集合竞价，15:00:00 整点价格尚未定稿（约 15:00:30 后才稳定）。要严格 15:00 改成 `"15:00"`，程序会自动重试等数据落定。

> `--serve` 常驻模式支持配置热加载（默认 60 秒检查一次），改时间不用重启。
> 计划任务模式则需要重跑 `install_task.ps1` 重新注册触发器（这不是缺陷，是计划任务本身的机制）。

## 五、把消息发到手机：选一个通道

在 `config.yaml` 的 `channels` 里把对应项的 `enabled` 改成 `true`，并填好密钥。
**密钥建议走系统环境变量**，不要写成明文：

| 通道 | 适合谁 | 密钥环境变量 | 备注 |
|---|---|---|---|
| **PushPlus** | 想用微信收，最省事 | `PUSHPLUS_TOKEN` | pushplus.plus 微信扫码领 token，免费额度够用 |
| **Server 酱** | 同上 | `SERVERCHAN_KEY` | sct.ftqq.com 获取 SendKey |
| **企业微信机器人** | 有企业微信群 | `WECOM_WEBHOOK` | 群设置→群机器人→复制 Webhook |
| **钉钉机器人** | 有钉钉群 | `DINGTALK_TOKEN` / `DINGTALK_SECRET` | 开了"加签"才填 secret |
| **飞书机器人** | 有飞书群 | `FEISHU_WEBHOOK` | |
| **邮件** | 想留档、最稳定 | `SMTP_USER` / `SMTP_PASS` / `MAIL_TO` | QQ 邮箱要用**授权码**，不是登录密码 |
| **Bark** | iPhone 用户 | `BARK_KEY` | 装 Bark App 后拿 key，支持归档 |

设置环境变量（Windows，设完要**重开终端**）：

```bat
setx PUSHPLUS_TOKEN "你的token"
setx SMTP_USER "you@qq.com"
setx SMTP_PASS "你的授权码"
setx MAIL_TO "you@qq.com"
```

配好之后先自测：

```bash
.venv\Scripts\python.exe run.py --test-notify
```

它会逐个通道尝试并打印成败原因，不用等到明天开盘才知道配错了。

**建议同时开两个通道**（比如 PushPlus + 邮件）。任何一个通道临时故障，另一条还能兜住。

## 六、定时运行方式

### 方式 A：Windows 计划任务（Windows 上推荐）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_task.ps1
# 换 python 路径的话：
powershell -ExecutionPolicy Bypass -File scripts\install_task.ps1 -PythonExe "C:\Python313\python.exe"
```

已启用的保障：

- `-StartWhenAvailable`：到点时电脑睡眠/关机，开机后会补跑
- `-RestartCount 3 -RestartInterval 5min`：进程异常退出自动重启
- `-MultipleInstances IgnoreNew`：同一时段不会重复启动
- `-ExecutionTimeLimit 15min`：卡死会被强制结束，不会永久占住

**要求**：电脑开机且用户已登录（任务以交互式登录运行）。笔记本合盖休眠会导致任务不执行 —— 这是本方案最大的单点风险，详见第八节。

### 方式 B：常驻进程（云服务器 / Linux）

```bash
.venv/bin/python run.py --serve
```

用 systemd 托管：

```ini
# /etc/systemd/system/jiaomei-tracker.service
[Unit]
Description=Jiaomei 000983 tracker
After=network.target

[Service]
WorkingDirectory=/opt/jiaomei_tracker
ExecStart=/opt/jiaomei_tracker/.venv/bin/python run.py --serve
Restart=always
RestartSec=10
User=root

[Install]
WantedBy=multi-user.target
```

## 七、稳定性机制（为什么它可以长期无人值守）

**取数容错**
- 行情：腾讯 → 新浪，逐个降级；日 K：腾讯前复权 → 新浪；资金流：东财日线 → 东财分钟线 → 3 个镜像域名轮询
- **资金流额外有一层 curl 兜底**：某些企业代理 / TLS 策略下，Python 的 HTTP 栈会与目标站点握手失败（报 `RemoteDisconnected`），而系统 curl 能正常访问。`fundflow_backend: auto` 会依次尝试 `requests` → `curl`（走系统代理）→ `curl --noproxy`（直连）。Windows 10/11 自带 curl.exe，不增加额外依赖
- 每层独立重试（默认 4 次），指数退避 + 随机抖动，避免多源同时被限流
- 数据合理性校验：价格 ≤ 0 直接判定为脏数据并切源；取到的股票名称与预期不符也会切源
- **拿不到的字段一律不编**：资金流全部失败时，报告里明确写"主力资金未取到（数据源不可用）"，
  并附一行明确标注口径的降级参考（内外盘主动买卖差），绝不把它冒充成主力净流入

**交易日守卫（不依赖外部日历）**
1. 周末直接跳过，不发网络请求
2. `config.yaml` 的 `holidays` 列表可手工补充休市日
3. 用**行情自身的时间戳**判断：如果拿到的行情日期不是今天（法定节假日会一直停在节前最后一天），判定为休市，本次不推送；判定前会先重试 3 次（每次隔 20 秒），避免真实交易日开盘瞬间的数据延迟造成误判

**推送容错**
- 每个通道独立重试 3 次，单通道失败不影响其他通道
- 全部通道失败 → 记 `send_failed` 日志并以非 0 退出码结束（计划任务里能看到失败状态）
- 取数全失败 → 仍会发一条"数据获取失败"提醒（`alert_on_failure: true`）。宁可收到坏消息，也好过完全静默

**幂等去重**
- 成功发送后写 `send_log`，同一交易日同一时段不重复发送 —— 计划任务的重试/补跑不会造成重复轰炸

**可观测**
- `logs/tracker.log` 轮转（2MB × 5），记录每一次取数来源、重试、推送结果
- `data/tracker.db` 存档每个交易日的行情与资金流，并记录每次运行状态
- `python run.py --status` 查看最近 25 条运行记录，一眼看出哪天哪次没发出去

**自动清理**
- 运行/发送日志按 `keep_days`（默认 400 天）清理；行情与资金流数据永久保留

## 八、风险与限制（务必读一遍）

1. **本机休眠 = 静默失联。** 计划任务只在机器开机并登录时执行。笔记本合盖休眠、系统更新强制重启期间的任务不会执行（`StartWhenAvailable` 只能在开机后补跑一次）。要求真正 7×24 稳定，请部署到云服务器（方式 B）。

2. **没有"心跳"就不知道它死了。** 建议：每天收盘那条能稳定收到，就说明程序还活着；如果某天该收到却没收到，先去 `logs/tracker.log` 和 `run.py --status` 查。更稳妥的做法是再加一条独立的每日固定消息做心跳（比如每天 09:00 发一条"程序存活"），这样"没收到"本身就是告警。

3. **数据源是非官方公开接口。** 没有 SLA，可能改字段、限流、加鉴权，甚至随时下线。程序做了多源降级，但**无法保证永久可用**。若某天全部源同时失效，属于外部依赖问题，需要人工更新取数逻辑。商用或需要更高质量数据请走持牌数据商。

4. **免费行情有延迟，不是逐笔实时。** 摘要中的价格有 3–15 秒甚至更长的延迟，"实时"实为准实时。不要用它做需要秒级精度的操作。

5. **不同数据源的主力资金口径不同。** 东财与腾讯自选股对"大单/超大单"的单笔金额分档标准不一致，同一天同一只票的主力净流入可能差几百万（实测 2026-09-24：东财 1347 万 vs 腾讯自选股 1366 万）。报告末尾标注了实际使用的来源与后端，**跨来源对比时不要混用**。

6. **东财日线资金流接口是间歇可用的。** 实测中它会在"取得到"和"完全无响应"之间反复切换。因此"近 N 日主力合计"由本地存档逐日累积，不再依赖该接口；单日主力净流入则由分钟级接口提供，稳定得多。这也意味着：**程序刚部署的那几天，近 5 日合计是不完整的**，连续跑满 5 个交易日后才完整。

7. **前复权数据会重算。** 腾讯日 K 用前复权，分红除权后历史价格会整体变化，历史均线随之改变。近 5 日走势在这段时间窗口内一般不受影响，但跨除权日对比需留意。

8. **涨跌停、停牌、除权日的特殊情况。** 停牌期间无行情，程序会按"行情日期非今日"处理并跳过；除权除息日的跳空不是真实下跌，本程序只做数据呈现、不做趋势判断，因此不会误报，但读数时需自己留意。

9. **合规。** 交易所行情有版权，本程序建议仅用于个人研究自用；不得高频抓取、不得二次分发或商用。配置文件里的密钥请注意保密。

10. **不构成投资建议。** 本程序只客观呈现价格、成交量、资金流等市场数据，不做任何趋势预测、不给买卖建议。所有决策请结合自身风险承受能力独立判断。

## 九、常见问题

**Q：`--dry-run` 能取到数，但计划任务里没收到消息？**
先看 `run.py --status`。若状态是 `skip_dedup`，说明该时段今天已经发过了；若是 `skip_stale`，说明行情日期不是今天（休市或数据源滞后）。

**Q：改完 `config.yaml` 的时间，第二天还是老时间发？**
计划任务模式下触发器是注册时写死的，需要重跑 `install_task.ps1`。`--serve` 模式则自动热加载。

**Q：推送报 `缺少必要配置项`？**
`enabled: true` 但密钥没读到。检查环境变量是否设好，以及设完后有没有**重开终端/重新登录**（`setx` 对已打开的终端不生效）。

**Q：报告里写"主力资金未取到"？**
东财资金流域名在你的网络下不通。按顺序排查：
1. 手动跑一次 `curl -sS "https://push2his.eastmoney.com/api/qt/stock/fflow/kline/get?lmt=0&klt=1&secid=0.000983&fields1=f1,f2,f3,f7&fields2=f51,f52,f53,f54,f55,f56"`，看是否有输出；
2. 若**不带 `--noproxy`** 无输出、带上 `--noproxy '*'` 有输出 → 是系统代理的问题，程序已内置直连兜底，可把 `fundflow_backend` 改成 `"curl"` 加快速度；
3. 若两种都没输出 → 该域名在你的网络被阻断，属外部不可控，程序会照常发其他字段并在报告里注明。

**Q：日志里 `curl: (56) schannel: server closed abruptly` 是什么意思？**
数据源主动断开了连接，通常表示该接口此刻不可用（东财日线接口间歇性如此），不是你的网络故障。程序会自动降级，无需处理。

**Q：企业微信报频率限制？**
群机器人约 20 条/分钟。本程序一天只发 3 条，正常不会触发；若你扩了很多标的和时段，需要加限流。

**Q：想同时盯多只股票？**
把 `target` 复制一份逻辑即可，但注意：日 K 是逐只串行拉取的，标的变多后单轮耗时会线性增长，建议控制在 20 只以内，并为每只单独建一个 `config` 与计划任务组合。
